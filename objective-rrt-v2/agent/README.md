# `ar`: agent-driven routes

An LLM agent (Claude Code) drives SM64 by keeping a **sliding window of objectives** filled. A background daemon solves them with the **rolling-horizon GA**: population 128, 600-frame plans, one frame committed per generation, a persistent shifted population, pink noise, and γ 0.99 per frame on the objective's ETA. Everything is recorded: inputs (as a commit tree), the objective history, **every GA generation's population**, sparse checkpoints and events. The agent can inspect any state, rewind to any frame or commit, branch, scrap objectives, and re-seed populations. How an agent should drive it is in [AGENT.md](AGENT.md).

```
cd objective-rrt-v2
CARGO_TARGET_DIR=target-agent nice -n 10 cargo build --release -p obrrt-agent --bin ar
AR=target-agent/release/ar
$AR new bob1 --threads 8                    # start: the TAS boot (menus only), castle grounds in control
$AR push --native Painting::Enter --key bob # objectives: native (preferred), lambda, spec, goto
$AR serve                                   # background daemon
$AR wait                                    # blocks until met / stalled / window_low / ...
$AR brief                                   # state, queue, events, objects, offers: what to read after every event
```

`ar help` lists every command.

## Sessions

`agent/sessions/<name>/` (gitignored). `ar new` makes the session current; `--s NAME` or `$AR_SESSION` picks another one.

| file | content |
|---|---|
| `session.json` | settings (`ar status --config`; change with `ar set KEY VALUE`) |
| `commits.jsonl`, `HEAD` | the commit tree. A commit has an id, parent, kind, objective, frame range from power-on, and an end-state summary. Kinds: `root`, `met`, `manual`, `abandoned`, `split`, `fork`, `import` |
| `wip.json`, `inputs/<id>.pads` | each segment's inputs (raw, 4 bytes per frame). The work in progress gets the id its commit will have |
| `queue.json`, `objectives.jsonl` | the queue (front first) and every objective's history: add, edit, status (queued / met with commit / scrapped), notes |
| `ckpt/` | checkpoints every `ckpt_every` (300) frames, at every commit and zone entry. ~2-20 KB each |
| `pop/<segment>.pj` | the population journal of that segment. A record holds one generation: the frame it was evaluated from, every plan's pads, origin, fitness, cut, first Done, end and ETA. Measured: ~10 KB per generation with keyframes every 64, i.e. ~300 KB per game second at one frame per generation |
| `events.jsonl` | the daemon's events (numbered `seq`) |
| `inbox/` | commands for the daemon. With no daemon, the CLI applies them itself, so the history is the same either way |
| `status.json`, `serve.pid`, `serve.log` | live status |

Nothing is deleted. A rewind keeps the work in progress as an `abandoned` commit. Landing inside a segment makes a `split` commit whose inputs are a prefix of it. Switching to any commit (`ar rewind cNNNN`) re-queues the objectives that are not met on the new path, or scraps them with `--drop`, and marks the ones that are met.

## Objectives

| selector | meaning |
|---|---|
| `{"native": KIND, "key": "sub\|alt", "near": [x,y,z], "within": R}` | an objective-rrt-v2 objective (`objectives/OBJECTIVES.md`, 142 kinds) as `Registry::generate` offers it at the state. Of that kind, the key must contain `key` (alternatives in order), it must be startable there, and it must have a finite ETA. Picks the nearest `near` by steer target, else the lowest ETA. Once resolved it is kept; an objective the Registry stops offering (it only makes object objectives within 5000) stays usable. `ar objectives` lists what is offered |
| `{"lambda": TEMPLATE \| "libname", "args": {...}}` | **Objective(b)**: a spec template bound at the base state b, when it becomes the front objective (again after a rewind). `"=EXPR"` strings are expressions; `"$name"` is an arg. Variables: `x y z yaw fv vy floor_y stars coins red_coins health frame level area`. Functions: `sin cos atan2` (degrees), `sqrt abs min max`. The zone defaults to b's. Templates live in `agent/lib/` (`ar lib add/list/show/retire`; retired ones stay on disk) |
| `{"spec": {...}}` | a spec objective, written on the fly (`../tools/spec/FORMAT.md`: phases, targets, predicates, penalties) |
| `{"goto": [x,y,z], "zone": Z, "r": 150, "grounded": true}` | inside the sphere; with `grounded`, standing or moving on the ground, controllable. `Z` is a zone as in tools/spec/FORMAT.md: `"castle"` (or `"lobby"`) is inside the castle (level 6), `"grounds"` the castle grounds (level 16), `"castle:1"` the lobby's area 1 |

Per-objective settings: `--rh '{"g": 4, "pop": 256}'` (more generations per committed frame, a larger population) and `--stall N`.

**The window** has two parts.
- **Forward:** the queue's first `window` (3) objectives. The controller's fitness folds through them in order: a plan that meets the current one within its 600 frames gets +300 and is then scored on the next one, so plans that set up the next objective score better. When the front one is met, its commit is cut, the window slides, and the population carries over. Committed frames are never revised by the forward part.
- **Backward** (`back_frames`, 600; 0 turns it off). This is the route bench's `window` method (`search/src/route/methods/window.rs`) with the rolling-horizon GA:
  - When an objective is met at frame F, the route is re-solved from B. B is the start of the objective that frame F − back_frames falls in, so B ≤ F − back_frames, rounded back to an objective boundary. B is never before the root. Dialog and menu objectives in the window replay their fixed programs, as the forward part does.
  - The re-solve is a fresh controller at or above the floor. It works through every objective met since B, then the forward lookahead. The incumbent route's inputs are offered as a time-aligned plan every step.
  - It is kept only if it meets the last objective before F. The new inputs then become new `met` commits, HEAD moves there, and the daemon continues with the re-solve's controller and population. The old route stays as a branch.
  - Events: `back_start`, `back_improved` (frames saved), `back_rejected`, `back_skipped`.
  - Every re-solve population is journalled: accepted ones under their new commits' ids, rejected ones as `pop/back-B-F-*.pj`.
  - Queue edits are applied during a re-solve. Any other command ends it and is then handled normally.

**Compute floor.** The user's gold standard is the minimum: population ≥ 128, plans ≥ 600 frames, ≥ 1 generation per step, 1 frame committed per step, pink noise. `set`, `new --set`, `--rh` overrides and `fork --rh` refuse anything below it, and the daemon raises any config it loads to it. More is always allowed (`--rh '{"g": 4, "pop": 256}'`).

**Modal states.** Dialogs, cutscenes and menus are pressed through (A on alternate frames) unless the front objective is itself a dialog or menu objective (`Dialog::*`, `Menu::SelectAct`, ...). Those objectives' fixed macros and policies play as they are. A star selector chooses the act this way: push `Menu::SelectAct` with the act's key before the painting.

## Events (`ar wait`, `ar events`)

| event | when |
|---|---|
| `met` | the front objective is met: its commit, frames, end state |
| `window_low` / `window_empty` / `waiting` | the queue holds fewer than the window / nothing / only unresolvable objectives |
| `stalled` | no new lowest ETA for `stall_frames` (600) frames on the front objective. It fires again at each doubling, and the daemon keeps working unless `stall_pause` is set |
| `unresolved` | the front objective is not offered at this state |
| `stuck`, `lost`, `failed`, `error`, `crashed` | every plan dies at once; the ETA is Lost; a fixed objective did not finish; a bad selector; the daemon stopped on an error |
| `front`, `resolved`, `pressed`, `zone`, `rewind`, `population`, `set`, `ack`, `fork`, `explore` | progress records |

## Inspecting (any `--at cNNNN | cNNNN:F | fF | -N`)

| command | what it shows |
|---|---|
| `state` | Mario (action names, timers, cap, floor/ceiling/wall with surface names), zone names, modal state |
| `progress` | stars per course, keys, every save flag by name (cap switches, doors, moat) |
| `objects [--near R] [--bhv S]` | every live object: behaviour, position, distance, action, `oTimer`, `oFlags`, health, interaction, hitbox, velocity |
| `geo [--r R] [--point x,y,z]` | static floors, walls and ceilings near a point; floor/ceiling probes; water; object surfaces; sm64-atlas traversability flags at the probes |
| `behavior NAME` | the behaviour script and the C functions it calls (file:line) |
| `level [--all]` | sm64-atlas level-script objects, warps and water for the zone |
| `objectives [--kind S]`, `eta SEL` | what is offered here, with start ETAs and targets |
| `diff A B`, `trace --from F --to F [--every N] [--eta ID]` | what changed; a per-frame trace with pads and an objective's ETA |
| `pop stats\|show\|seed [--seg S] [--record I \| --at fF]` | the journal; `seed` loads a recorded population into the live controller |

## Wider search (the agent's choice)

- `ar fork N SEL [--frames F] [--rh JSON]`: N independent controllers (different rng salts) from the path's end on one objective. Each result is kept as a side-branch commit; `ar rewind <commit>` adopts one.
- `ar explore [--minutes M] [--threads T] [--frames F]`: a bounded obrrt2 tree from the path's end (the latest `builds/*/obrrt2`, screen.sh's settings, `OBRRT_BOOT_NOWAIT`). It reports zones reached, first star nodes and objective kinds; `ar explore import RUN NODE` adds a node's path as a branch.

## Checks (`ar selftest`)

Run on smoke1 (2026-11-11, at the castle entry on the BoB painting objective; 4 threads, busy machine). All passed:

1. Checkpoints: 21/21 random frames, `load_at` byte-identical to a replay from power-on.
2. Determinism: 40 committed pads identical with 4 threads and with 1.
3. Journal: 40/40 generations reconstruct exactly.
4. Rewind: a controller restored from the journal at frame 2321 commits the same next 20 pads as the original run.

Backward window (smoke2, 2026-11-11, back_frames 600): the tree climb was re-solved from 1646 and met 1 frame sooner (30 s). Then the tree + bridge were re-solved from 1646 and the bridge was met at 1847 instead of 1851 (99 s); the tree segment went from 81 to 78 frames.

Speed at the gold standard: ~197 k emulated frames/s on 4 threads, i.e. ~2.6 committed frames/s (128 × 600 frames per committed frame).
